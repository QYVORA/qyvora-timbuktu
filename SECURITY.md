# Security Policy

## Supported Versions

Only the latest tagged release receives security updates.

## Reporting a Vulnerability

If you discover a security vulnerability in Timbuktu, please report it privately by emailing the QYVORA OffSec team at **qyvorasec@gmail.com**. **Do not open a public GitHub issue.**

We will acknowledge receipt within 48 hours and provide an estimated timeline for a fix. Once the fix is released, we will credit the reporter (if desired) in the release notes.

## Contact

- **Website:** https://qyvora.org
- **Security contact:** qyvorasec@gmail.com
- **Organisation:** QYVORA OffSec — Tamale, Ghana

## Scope

This policy covers the Timbuktu source code, build pipeline, and release artifacts. Issues related to the forensic case files being analyzed (e.g., evidence of an incident discovered *by* Timbuktu) are out of scope — those should be reported to appropriate authorities or the incident response team.

**Note:** Timbuktu performs offline analysis of case files only. It never modifies evidence and maintains chain of custody. Live host acquisition is not implemented.

## Responsible Disclosure

We ask that you give us reasonable time to patch and release a fix before any public disclosure.
